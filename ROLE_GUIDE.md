## Roles and Pages Guide

This document explains every role, each dashboard tab, and all main user pages in the frontend-only build.

## Stakeholder Roles

### ADMIN
System administration and oversight for the entire platform.
- **Core responsibilities**: global oversight, security posture, governance
- **Operational focus**: platform metrics, alerts, cases, audit visibility
- **Collaboration**: inter-role coordination and escalation management

**Dashboard tabs**
- **Overview**: high-level system metrics, alert summaries, system health
- **Users**: user activity, exports, admin tools, and user management
- **Alerts**: emergency alert monitoring and status tracking
- **Cases**: case queue overview and status changes
- **Messages**: inter-role communications and announcements
- **Security**: security monitoring and posture checks
- **Analytics**: dashboards and trends (charts/visuals)
- **Operations**: quick actions and system operations toolkit
- **Training**: learning modules and training requests
- **Compliance**: compliance checklist and review actions
- **Resources**: resource library and download bundle
- **Audit Logs**: audit history and incident reporting
- **Support**: support contacts and ticket creation
- **Partners**: partner directory and call requests
- **Scheduling**: event scheduling and upcoming calendar
- **Impact**: impact highlights and report generation
- **Geo Intel**: hotspot monitoring and geo updates
- **Field Ops**: deployments and mission launches
- **Inventory**: supplies monitoring and restock requests
- **Funding**: funding tracker and requests
- **Risk**: risk intelligence and mitigation plans
- **Data Sharing**: secure data sharing policies and packs
- **Transport**: transport logistics and dispatch
- **Case QA**: case quality reviews
- **Grant Reports**: grant reporting and submissions
- **Governance**: data governance policies
- **Contracts**: partner contract tracking
- **Crisis Comms**: crisis bulletin coordination
- **Regional**: regional insight tracking
- **Volunteers**: volunteer management
- **Collaboration**: partner coordination hub
- **Settings**: system configuration and admin controls

## Main Pages (All Users)

These pages are available from the main app navigation.

- **Home** (`/`): landing and feature overview
- **Chatbot** (`/chatbot`): SRHR guidance and Q&A
- **Videos** (`/videos`): video library and modal viewer
- **Articles** (`/articles`): SRHR articles and guides
- **SMS** (`/sms`): SMS interface and offline queue
- **SMS Alerts** (`/sms-alerts`): SRHR reminder subscriptions and modals
- **Stories** (`/stories`): storytelling feed and story creation modal
- **Clinics** (`/clinics`): clinic finder and verification modal
- **Safe Spaces** (`/safe-spaces`): safe space list and details modal
- **Tracker** (`/tracker`): health/cycle tracker and entry modal
- **Games** (`/games`): interactive learning hub
- **Consent Game** (`/consent-game`): consent scenarios and score flow
- **Inclusive Support** (`/inclusive-support`): inclusive services/resources/groups
- **Emergency** (`/emergency`): emergency contacts, panic flow, logs
- **Mentorship** (`/mentorship`): mentor list and request modal
- **Offline Mode** (`/offline`): offline guidance and tools
- **Notifications** (`/notifications`): notification center
- **Tutorial** (`/tutorial`): onboarding and training
- **QR Verification** (`/qr-verification`): QR generation/verification tools
- **Visual Accessibility** (`/visual-accessibility`): visual aids and settings
- **Motor Accessibility** (`/motor-accessibility`): motor accessibility tools
- **Hearing Accessibility** (`/hearing-accessibility`): hearing accessibility tools
- **Cognitive Accessibility** (`/cognitive-accessibility`): cognitive aids and settings
- **Medication Order** (`/medication-order`): medication ordering workflows
- **Secure Map** (`/secure-map`): secure mapping and verification modals
- **Settings** (`/settings`): user settings and account tools
- **Dashboard Access** (`/dashboard`): stakeholder access and role routing

## Notes
- Stakeholders select a role and continue to OTP login; secret codes are not required in testing.
- Backend integration will be added later; current flows run entirely on frontend mock data.
